# 合同审查

## 目标
审查中文法律合同，以指定方视角识别风险条款、缺失条款和模糊表述，输出分级修改建议。

## 适用场景
**正向触发（应该用）：**
- 用户提供一份中文合同全文并要求审查
- 用户明确指定了己方身份（如「我是甲方」「我方是委托方」）
- 用户要求「提出修改意见」「看有没有坑」「法律风险」

**排除条件（不该用）：**
- 合同为英文或其他语言
- 用户仅要求解释某个法律概念而未给出合同全文
- 用户要求的是「起草合同」而非「审查已有合同」
- 合同涉及高度专业领域且技能规则库无覆盖（需声明能力边界）

## 输入
- **contract_text** (必填)：合同的完整文本
- **party_role** (必填)：我方在合同中的身份，如"甲方/委托方/实际股东"
- **concerns** (可选)：用户特别关注的维度，如"违约金""竞业限制"

## 输出
输出应包含以下结构：

```markdown
## 一、协议逐条分析
每条按「问题 → 风险分析 → 修改建议」三段式输出

## 二、总结：核心修改清单
| 优先级 | 条款 | 问题 | 修改方向 |

## 三、谈判要点提示
教用户该条款背后的博弈逻辑
```

每个修改建议必须包含**可落地的改法**（改写后的条款文本），不要只写「建议修改」。

## 流程

### 步骤1：身份定位
- 解析 `party_role`，确定审查视角
- 检查点：我方权益方向已确定（是增强保护还是减轻义务）
- 如用户未指定，主动追问

### 步骤2：全文结构扫描
- 快速扫描合同章节和条款编号
- 识别：是否有缺失条款编号（跳号）、是否有残缺条款（截断文本）
- 检查点：已列出所有结构异常点

### 步骤3：逐条四性审查
按以下四个维度审查每个条款：
1. **完整性**：条款是否完整（没有断尾）
2. **模糊性**：是否有「合理期间」「及时」「尽力」等模糊词
3. **风险倾向**：该条款对我方偏向有利还是不利
4. **可执行性**：条款约定的义务是否有明确的时间、方式、后果

- 检查点：每个条款至少覆盖了四性中的两项

### 步骤4：缺失条款识别
检查是否缺少以下常见保护条款：
- [ ] 单方解除权
- [ ] 配偶/继承人知情同意
- [ ] 违约责任的具体化
- [ ] 送达地址确认
- [ ] 争议解决方式（管辖/仲裁）

- 检查点：输出中列出了具体的缺失条款名称和应补的位置

### 步骤5：管辖与争议条款专项
- 检查管辖约定是否合法
- 检查是否为「原告所在地」（双刃剑条款，标记高风险）
- 给出具体替代方案（仲裁/甲方住所地）

- 检查点：管辖条款建议附带了法律依据

### 步骤6：生成分级修改清单
- 🔴极高：可能导致权益丧失的条款
- 🟠高：可能导致重大损失的条款
- 🟡中：可能增加摩擦成本的条款
- 🟢低：措辞优化建议

- 检查点：极高优先级 ≥ 1 项（否则可能漏检）

### 步骤7：输出谈判要点
对每个核心修改项，解释「为什么该这么谈」，帮助用户理解博弈逻辑。

- 检查点：每个要点 ≤ 3 句话，不展开法理论述

## 规则清单

### 违约金相关
- 【必须】违约金建议必须区分「补偿性违约金」和「惩罚性违约金」
- 【必须】讨论违约金司法上限时，引用《民法典》第585条和《合同编通则解释》第65条
- 【禁止】不得将民间借贷的「24%年利率保护上限」跨界引用为违约金司法标准
- 【禁止】不得声称「年化24%以内的违约金法院一般不主动调低」
- 【建议】违约金数额建议采用「实际损失 + 惩罚性违约金 + 超额追偿」三层结构
- 【建议】逾期付款违约金利率建议优先使用「LPR四倍」（约12.4%），这是当前最稳健的标准

### 管辖与争议
- 【必须】识别「原告所在地」管辖约定的双刃剑风险
- 【必须】提示公司类纠纷可能存在公司住所地专属管辖
- 【建议】优先推荐仲裁（一裁终局、保密、不受地域管辖限制）
- 【建议】次选方案为「甲方住所地人民法院」

### 期限与解除
- 【必须】标记「自动续期」条款的风险——容易忘记异议导致被动续期
- 【必须】检查是否缺少单方解除权
- 【建议】所有期限性约定必须有明确的起算点和触发条件

### 不可量化的模糊表述
- 【必须】标记以下词语并要求量化：合理期间、及时、尽力、酌情、适当、必要
- 【建议】每个量化的替代方案给出具体数字和时间窗口

### 家庭变故风险
- 【必须】如合同涉及代持、委托、合伙，检查是否有配偶知情/继承排除条款
- 【建议】建议将配偶知情同意书作为合同附件

### 引用来源规范
- 【必须】每引用一条法律标准，附上法规全称和条款号
- 【禁止】使用「司法实践表明」「通常认为」「行业惯例」等模糊来源描述，除非能给出具体裁判规则编号
- 【建议】无法给出法规来源的判断，标注为「基于法理分析」而非「基于司法实践」

## 已知失效模式

### 模式1：违约金司法上限的规则误引
- 描述：审查违约金条款时，引用了民间借贷的24%年利率上限作为违约金司法保护标准
- 场景触发：审查到违约金比例/费率条款时
- 原因：训练数据中大量法律自媒体混淆了民间借贷利率上限和违约金司法调整标准
- 对策：违约金相关建议必须锁定在《民法典》585条 + 《合同编通则解释》65条框架内，不得跨界

### 模式2：遗漏配偶知情条款
- 描述：审查股权代持协议时，未提示补充配偶知情和继承排除条款
- 场景触发：涉及代持、委托持股、股权转让的合同
- 原因：注意力集中在合同主条款上，遗漏了外部风险（第三方主张权利）
- 对策：步骤4（缺失条款检查）中明确列出「配偶知情」为必检项

### 模式3：管辖权推荐的过度自信
- 描述：直接推荐某个管辖地，未提示公司住所地专属管辖的例外
- 场景触发：合同涉及公司股权、股东资格确认
- 原因：过度拟合了「原告所在地」这个表面有利的约定
- 对策：管辖权建议必须附带例外说明——"如是公司类纠纷可能受专属管辖限制"

### 模式4：修改建议过于抽象
- 描述：输出「建议修改此条」而不给出具体改法文本
- 场景触发：条款分析量大的合同时，为节省上下文省略具体改法
- 原因：token 优化冲动压倒了可用性要求
- 对策：每条建议必须附带可粘贴使用的改后条款文本
